Capstone Project

My Capstone project is an in-progress AI-enabled SOC Engine focused on automating triage for malsite alerts. The system uses MCP-style services to pull alerts from Jira, extract domains or URLs, enrich them with VirusTotal, classify them, and post a structured triage summary back into the original Jira ticket.

Goals

  • Reduce manual SOC workload by automating repetitive malsite alert investigation steps.
  • Improve triage speed and consistency through a standardized end-to-end workflow.
  • Generate explainable outputs that analysts can use for downstream response decisions.
  • Build a system that is extensible for future verdict types, enrichment sources, and workflow improvements.

Team Process So Far

  • Completed project setup, technical design, and development environment preparation.
  • Built the core Jira and VirusTotal integrations needed for alert retrieval and enrichment.
  • Implemented indicator extraction for domains and URLs from alert metadata.
  • Reached an MVP that can classify alerts, generate triage summaries, and auto-post results to Jira.
  • Moved into spring-quarter refinement focused on testing, accuracy improvements, confidence thresholds, and feature expansion.

Milestones Completed

  • Milestone 1: Project setup, project charter, PRD, architecture planning, and API access confirmation.
  • Milestone 2: Core MCP server functionality for Jira retrieval, VirusTotal querying, and domain/URL extraction.
  • Milestone 3: classification logic, triage summary generation, auto-posting to Jira, and MVP demo readiness.
  • Current spring work: Refinement, testing, logging, error handling, confidence thresholds, and expanded features.

My Individual Contributions & Learnings

  • Strengthened my skills in backend system design, API integration, and workflow automation.
  • Learned how to build software for real SOC workflows rather than just isolated technical demos.
  • Focused on making the system more reliable through logging, error handling, and maintainable structure.
  • Gained experience balancing MVP delivery with longer-term product thinking and extensibility.
  • Developed a better understanding of how constraints like API limits, alert variability, and non-production environments shape engineering decisions.

Takeaways

One of the biggest lessons from this project has been learning how to translate an operational problem into a practical engineering workflow. Instead of trying to overbuild the system, our team focused first on a clear MVP: retrieve the alert, extract the indicator, enrich it, classify it, summarize it, and write the result back to Jira. That process taught me how real-world software projects succeed by being iterative, explainable, and useful.
